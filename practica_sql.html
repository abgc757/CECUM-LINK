Módulo 1 — SELECT básico

Teoría + Ejercicios
📖 Conceptos

El comando SELECT recupera datos de una o más columnas de una tabla.

Sintaxis base SELECT columna1, columna2 FROM tabla;
📌 Ejemplo 1 — Todos los usuarios
SELECT id, username, full_name, role
FROM users;

📌 Ejemplo 2 — Limitar resultados con LIMIT
SELECT id, title, event_date
FROM events
LIMIT 5;

Trae solo los primeros 5 eventos registrados.

📌 Ejemplo 3 — Alias con AS
SELECT full_name AS "Nombre completo",
       email      AS "Correo"
FROM users;
✏️ Ejercicios
Ejercicio 1.1 ● Fácil
Escribe una consulta que muestre el username y el email de todos los usuarios registrados en la plataforma.
Usa SELECT con las columnas separadas por coma y FROM con el nombre de la tabla correcta.
Ejercicio 1.2 ● Fácil
Muestra el título, la fecha del evento y la ubicación de los primeros 10 eventos registrados.
Recuerda usar LIMIT al final de tu consulta para restringir el número de resultados.
Ejercicio 1.3 ● Medio
Consulta el contenido y la fecha de creación de las publicaciones, usando el alias "Publicación" para content y "Fecha" para created_at.
Usa la palabra clave AS después de cada columna para asignarle un alias: columna AS "Alias".

Módulo 2 — WHERE y filtros

Teoría + Ejercicios
📖 Conceptos

WHERE filtra filas según una condición. Solo las filas que cumplen la condición aparecen en el resultado.

Operadores comunes =   !=   <   >   <=   >=   LIKE   IN   BETWEEN   IS NULL   AND   OR   NOT
📌 Ejemplo 1 — Filtrar por rol
SELECT full_name, email, role
FROM users
WHERE role = 'student';
full_nameemailrole

Laura Martínezlmartinez@cecum.mxstudent

📌 Ejemplo 2 — LIKE para búsqueda parcial
SELECT full_name, email
FROM users
WHERE email LIKE '%@cecum.mx';

El % es un comodín que representa cualquier cantidad de caracteres.

📌 Ejemplo 3 — Múltiples condiciones con AND / OR
SELECT full_name, role, approved
FROM users
WHERE role = 'student'
  AND approved = true;
✏️ Ejercicios
Ejercicio 2.1 ● Fácil

Agrega una cláusula WHERE después del FROM con la condición role = 'teacher'.
Ejercicio 2.2 ● Fácil

La columna read es de tipo BOOLEAN. Filtra con WHERE read = false.

Combina dos condiciones con AND: una para approved = true y otra con LIKE '%a%' para el username.
Ejercicio 2.4 ● Difícil

Módulo 3 — JOIN entre tablas

Teoría + Ejercicios
📖 Conceptos

JOIN combina filas de dos tablas usando una columna en común (clave foránea → clave primaria).

Tipos de JOIN más usados INNER JOIN — solo filas que coinciden en ambas tablas.
LEFT JOIN — todas las filas de la tabla izquierda; NULL donde no hay coincidencia a la derecha.
📌 Ejemplo 1 — Publicaciones con nombre de autor
SELECT p.id, p.content, u.full_name AS autor
FROM posts p
INNER JOIN users u ON u.id = p.user_id;
idcontentautor
1Bienvenidos al nuevo ciclo…María García López
2Recordatorio: entrega el viernes…Juan Pérez Ruiz
📌 Ejemplo 2 — Mensajes con remitente y destinatario
SELECT m.id,
       m.content,
       s.full_name  AS remitente,
       r.full_name  AS destinatario
FROM messages m
JOIN users s ON s.id = m.sender_id
JOIN users r ON r.id = m.receiver_id;

Se hace doble JOIN a la misma tabla users con alias distintos (s = sender, r = receiver).

📌 Ejemplo 3 — LEFT JOIN (grupos sin eventos)
SELECT g.name, e.title AS evento
FROM groups g
LEFT JOIN events e ON e.group_id = g.id;

Módulo 4 — GROUP BY y funciones de agregación

Teoría + Ejercicios
📖 Conceptos

GROUP BY agrupa filas con el mismo valor en una columna y permite calcular totales por grupo.

Funciones de agregación COUNT(*) — cuenta filas  |  SUM(col) — suma  |  AVG(col) — promedio  |  MAX(col) — máximo  |  MIN(col) — mínimo
📌 Ejemplo 1 — Cantidad de usuarios por rol
SELECT role,
       COUNT(*) AS total
FROM users
GROUP BY role
ORDER BY total DESC;
roletotal
student142
parent38
teacher12
moderator3
📌 Ejemplo 2 — HAVING (filtro sobre el grupo)
SELECT subject,
       AVG(grade_value) AS promedio
FROM grades
GROUP BY subject
HAVING AVG(grade_value) >= 7.0
ORDER BY promedio DESC;

HAVING filtra grupos (se aplica después de GROUP BY). WHERE filtra filas (antes de agrupar).

✏️ Ejercicios
Ejercicio 4.1 ● Fácil
Cuenta cuántos mensajes ha enviado cada usuario (por sender_id). Muestra sender_id y el total de mensajes enviados.
Usa GROUP BY sender_id y COUNT(*) para contar los mensajes de cada remitente.
Ejercicio 4.2 ● Medio
Calcula el promedio de calificaciones por materia. Muestra solo las materias cuyo promedio sea mayor a 7.5, ordenadas de mayor a menor promedio.
Combina GROUP BY subject con AVG(grade_value) y usa HAVING para filtrar el resultado.
Ejercicio 4.3 ● Difícil
Muestra el nombre de cada grupo junto con el número de tareas que tiene. Incluye también los grupos sin tareas (deben aparecer con 0). Ordena por número de tareas de mayor a menor.
Usa LEFT JOIN de groups a tasks para incluir grupos sin tareas. Luego agrupa por g.id y g.name, y usa COUNT(t.id) para contar tareas (COUNT de columna NULL retorna 0).

Módulo 5 — Subconsultas

Teoría + Ejercicios
📖 Conceptos

Una subconsulta es una consulta dentro de otra. Puede ir en WHERE, FROM o SELECT.

¿Cuándo usar subconsultas? Cuando necesitas filtrar por un resultado calculado, comparar con un agregado o reutilizar un conjunto de filas calculado previamente.
📌 Ejemplo 1 — Usuarios que han publicado al menos una vez
SELECT full_name, email
FROM users
WHERE id IN (
  SELECT DISTINCT user_id
  FROM posts
);
📌 Ejemplo 2 — Alumno con la calificación más alta
SELECT u.full_name, g.subject, g.grade_value
FROM grades g
JOIN users u ON u.id = g.student_id
WHERE g.grade_value = (
  SELECT MAX(grade_value) FROM grades
);
✏️ Ejercicios
Ejercicio 5.1 ● Medio
Muestra los usuarios que nunca han enviado un mensaje. Usa una subconsulta con NOT IN sobre la tabla messages.
WHERE id NOT IN (SELECT DISTINCT sender_id FROM messages)
Ejercicio 5.2 ● Medio
Lista los grupos que tienen más tareas que el promedio de tareas por grupo. Muestra el nombre del grupo y su cantidad de tareas.
Agrupa groups con COUNT(tasks) y usa HAVING COUNT(...) > (SELECT AVG(cnt) FROM (SELECT COUNT(*) AS cnt FROM tasks GROUP BY group_id) sub).
Ejercicio 5.3 ● Difícil
Obtén el nombre del alumno y su calificación más alta de cada materia. Solo muestra alumnos cuyo promedio general sea mayor al promedio de toda la plataforma.
JOIN grades con users, GROUP BY student_id, usa MAX(grade_value) y filtra con HAVING AVG(grade_value) > (SELECT AVG(grade_value) FROM grades).
